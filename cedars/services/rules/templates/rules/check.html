Other ways to check

  • From your own system, through the API. POST /api/v1/rules/check with the file, the module (claims or budgets), the table, and optionally the rule set's ID and the filing year returns these findings as JSON or CSV. Use an API token from your account page; the API description lists the fields.
  • Without sending a file. Each rule set's page offers its rules as JSON with how each rule is checked and the value lists it reads, for checking files in your own systems. {% for ch in choices %}{% if ch.in_force %}{{ ch.checker.label }} rules in force (JSON){% if not forloop.last %}; {% endif %}{% endif %}{% endfor %}.
  • With ReCET installed. recet preflight --preflight-only --filing-validation claims --filing-year 2028 --measures Measure.csv (or budget_filing) runs CEDARS' rules as the engine release ships them. When this site's version is newer than the engine's, the page, the API or the JSON give the rules in force here.

The upload also runs the module's checks that need the whole filing (its other tables, earlier confirmations, eTRM's values for deemed claims, the program registry), so a file that passes here can still get findings on upload.
