First steps

  1. Open New run and upload one .zip with Measure.csv and, optionally, ProgramCost.csv, or ReCET's job workbook (.xlsx) with a Measure sheet and, optionally, a ProgramCost sheet. ReCET's optional input files (run parameters, 8,760 electric profiles, gas monthly profiles) go under Optional input files, in the zip, or as sheets of the workbook; their columns are in ReCET's input fields. The program registry and the allocation version stand in for a job's own program metadata and statewide factors. Templates to download, at the top of New run, has the engine's own template for each file.
  2. Choose who the run is for, the engine and the ACC (Which ACC applies to my filing? on the page helps). ReCET's own calculation can also price the job on a second ACC (Compare with another ACC: Results then has a tab for each ACC and one comparing them), set CET's First Year and market effects, price each ACC component separately, and write the combined 8,760 electric load profile for the years you choose. Priced for flags records whose ACC does not apply to their program year for claims, any filing, or one named budget filing; nothing is stopped.
  3. Choose Start the run, or Check the inputs only. The run's page shows its progress and the engine's log while it runs, then the input check (what stopped the run, what could not be priced and every other finding), its files, one at a time or all in one .zip, and its results.
  4. A run you leave unnamed is named after its job file (or draft) and its ACC. What each cost-test set prices, under Pricing, lists the registered sets and their tests; an analysis run may take a cost-test set file of your own instead, recorded with its SHA-256 (a filing, or a run with filing checks or Priced for, takes a published set). The run page explains its totals and says when retention deletes the run.

Build a cost-test set

Anyone signed in can build a cost-test set for their own analysis runs on Reference data, Cost-test sets, Build a set. Only the CPUC registers a set for everyone and pins a set to a filing.

  1. Start from a copy of a registered set, one of your own, a set the engine ships, a set file you upload (a YAML file, written by hand or downloaded from a set's page) or nothing. A file's parts the set format does not have are set aside and shown on Review, never written out. Tick Share it with your organization to let the people there who may start runs see and change it.
  2. Work through the steps: Set (its id, built from the workstream and first program year, its label, version and program years), Pricings (which ACC rows and discount rates each pricing uses), Streams the engine prices (the values the engine prices: include or leave out each one, and choose its pricings, unit and definition) and Streams from input columns (a value of your own, such as a health benefit, from Measure columns you name), Aggregates (columns such as TotalSystemBenefit that add up streams in one pricing) and Tests (each test's benefits, costs, share of the program costs, variants and outputs, in the order runs show them).
  3. Every save is checked by the engine's own validator, and each problem is listed at the top of the step it belongs to and counted beside the step's name. Review lists them all, shows the set in the engine's words, lists what changed since the set it was copied from, and offers its file.
  4. Price an analysis run on it from New run's Or one of my cost-test sets, or download the file and use it as your own cost-test set file. A set everyone could use can be offered to the CPUC from Review, with a note; the CPUC registers it or declines it with a reason, which you are sent. A CPUC cost-test pack manager can register a set with no problems as a draft pack; the engine on the server records its engine check at once, and the manager publishes it.

Learn more

  • Edit inputs: edit a small job as a spreadsheet (paste from Excel, add and copy rows, undo) or row by row, or add a measure from eTRM. End uses are offered and checked from the impact-profile library in force; Check with the engine runs the engine's whole input check on the tables without pricing and marks the cells it names; a draft downloads as a job zip or a job workbook.
  • Output templates: choose the columns a run's file holds and their order, from the list of every field a run writes.
  • Impact profile library: the hourly profiles measures name, and custom uploads (the Impact profiles guide).
  • Reference data and cost-test sets: the ACCs, allocation factors and cost-test sets a run is pinned to.
  • From a finished run's page, open its Results or compare it with another run. On both, Choose columns works as an output template does: columns you can add on the left (searched by name or definition), the columns shown on the right in the order the table shows them, with buttons to add, remove and reorder them. Save the columns shown as a named view to pick again for any run.
  • From a finished run's page, you can also choose Rerun with different settings: New run filled in from the run, with its job file and optional input files used again unless you upload others. Your own runs (for Only me) can be deleted, with their files, once they end; an organization's runs stay until retention removes them.
  • Engine documentation: the engine's full reference: input formats, input fields, output fields with every formula, the method and the cost tests.
