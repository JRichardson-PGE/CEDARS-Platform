Every change to CEDARS' specifications, validation rules, limits and system is announced in the release notes before it takes effect. A note is published at least the usual notice period before its changes take effect; one published at shorter notice says why. A published note never changes: if a plan changes, the note is withdrawn (it stays listed, marked, with the reason) and a new one is published.

For everyone

  • Release notes: coming changes first, then the release this site runs and every earlier note. Subscribe to hear of new notes.
  • Limits: every limit CEDARS applies now (upload sizes, run sizes, download sizes, API rates), with any change that is coming and its date.
  • Specification change log: every version of the data dictionary, the value lists and the rule sets.
  • CPUC-mandated changes: each decision or resolution that changes CEDARS' data or calculations, what it requires, when it takes effect, how far CEDARS has implemented it and where CEDARS carries it.

For CPUC system administrators

  1. Write a release note: list each change with its kind, the part of CEDARS it touches, what changes and what people need to do, then publish it with a date after today. Publishing tells everyone subscribed and shows a banner on every page until it takes effect.
  2. The check at the top of that page says whether the running release has its note, whether every limit in effect matches what the site applies, and whether the user guides were revised for the releases that changed their part of CEDARS.
  3. Keep the register: draft an entry for each decision or resolution, link the rule set, dictionary version, value list, field, reference data or release note that carries it, and publish it. The register is public: enter only what the CPUC's public document says.
