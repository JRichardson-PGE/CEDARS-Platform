Reference data are what the calculation engine and the filings read besides your own inputs: the avoided cost calculators (ACCs), eTRM packs, the impact profile library, statewide allocation factors and cost-test sets. Every run and every filing records the versions it used, so a result can always be traced to its data.

Data packs

  1. Data packs lists every pack with its status and files, each with its SHA-256 checksum.
  2. A draft pack can be used for analysis runs but not for filings. A pack is published once it passes its tie-outs; a published pack is never changed, and a withdrawn one keeps the runs that used it.

Acceptance checks

  • Pack acceptance checks lists the checks each kind of pack must pass before it is published, such as reconciling an ACC to its published workbook. CPUC system administrators add a check or retire one, with a reason; a check is never edited, and a published pack keeps the checks it was published under.
  • A check's result is recorded on the pack's page by uploading the JSON report the reconciliation script or the engine's tie-out wrote. The report says whether the check passed ("passed" true or false, or "status" PASS or FAIL); a report naming a file's SHA-256 must name one of the pack's files.

eTRM permutation packs

The CPUC loads eTRM's permutations downloads (CSV) from Upload eTRM permutations as a draft pack, indexed by Measure Detail ID, and publishes it on its page. Claims check deemed records against the published pack in force. The avoided-cost and impact-profile library packs are registered from storage instead: they are gigabytes.

Statewide allocation factors

The statewide allocation factors are each funding PA's share of each statewide program, by year. Anyone can read the confirmed versions; signed in, you see every version. A confirmed version never changes. The funding PAs manage the factors: a member with the permission loads a draft from a factor file and confirms or discards it, and the other funding PAs are told. A run that names no version uses the most recently confirmed one for its program year. A version's page shows its factors in a table (narrow it by program year or program) and offers them as a CSV in the layout ReCET reads.

A factor file starts from the template on the allocation page: each statewide program and year, its PercentElectric (required) and each funding PA's electric and gas factors, with at most 4 decimal places each (a longer value refuses the file). Each fuel's factors must add up to exactly 1.0000. A 100% electric program's gas factors equal its electric factors (and a 0% electric program's electric factors its gas factors), so its savings in the other fuel are still allocated; left blank, they are copied. The weighted factors are not in the file: each is PercentElectric × electric + (1 − PercentElectric) × gas, rounded to 4 decimal places, and where the rounded values do not add up to exactly 1.0000, the PA whose value was closest to rounding the other way moves by 0.0001 first until they do.

Cost-test sets

  • A cost-test set says which value streams each cost test adds up and how it shares the program costs. Every run is pinned to one. A filing is priced only on a published set: the one its filing setup names, or the one in force for its first program year.
  • Anyone signed in may build a set, usually from a copy of a registered set, and price their own analysis runs on it from New run. Only the CPUC registers a set for filings.
  • The builder shows each test as a formula, TRC = (ElecBen + GasBen + adder(TaxCredits)) / (ElecSupplyCost + share x ProgramCosts), and a test can be typed that way. Streams are joined by +, each once; adder(X) adds X to the test's benefits without counting it in the benefits the program costs are shared by; share x ProgramCosts is the test's own share of the program costs and share(TRC) x ProgramCosts takes TRC's.
